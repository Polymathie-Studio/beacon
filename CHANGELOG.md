# Changelog

All notable changes to BEACON are recorded here. This project has not yet cut a numbered release; changes below are unreleased. BEACON is in progress toward the full findability set (see the scope note); this is Tier 1.

## Unreleased

### Added

- Tier 3, the findability auditor and llms.txt, completing the findability set (Tiers 1 to 3): `audit(html)` scans a page's HTML and returns `{ ok, errors, warnings, passed }`, checking the head essentials, Open Graph and Twitter, JSON-LD validity, and the canonical-versus-og:url agreement invariant. It reads the served markup (to test the render gate, audit the raw server response), and BEACON does not fetch, keeping it pure. `llmstxt(data)` serializes an llms.txt, labeled emerging and not consumed by the major engines. Both are zero-dependency functions with no React component. BEACON now covers the set and stays 0.x until a numbered release is cut.
- Tier 2, structured data and site files: `jsonLd(schema)` serializes one or several schema.org objects (combined under `@graph`) into a JSON-LD script tag, escaping the `</script>` sequence so it cannot break out, with builders `organization`, `website`, `article`, `product`, and `breadcrumb`. `sitemap(urls)` serializes a `sitemap.xml` from canonical URLs (strings or objects with lastmod, changefreq, priority). `robots(opts)` serializes a `robots.txt` for crawl control only, keeping index control in the head where it belongs. `icons(data)` returns the favicon and icon link tags, and `manifest(data)` serializes a Web App Manifest. The React binding adds `JsonLd` and `Icons` (using the core serialization) and re-exports the schema builders; the sitemap, robots, and manifest serializers are build-time files with no component.
- Tier 1, the head essentials plus social cards: `head(metadata)` returns the findability `<head>` tags as a string for server-render or build time, so the metadata lands in the server HTML where non-JS crawlers and social scrapers read it. It emits, in order, a UTF-8 charset, a viewport, the title, meta description, canonical link, an optional robots directive, the Open Graph tags (title, type, url, description, site_name, locale, and image with its sub-properties), and the Twitter card (which falls back to Open Graph). `og:url` defaults to the canonical so the two agree, and every value is HTML-escaped. A `htmlAttrs(metadata)` helper returns the `lang` attribute for `<html>`.
- The React binding (`beacon-ui/react`): `Head`, which renders the same tags as elements; React 19 hoists them to `<head>`.
- Build and SSR-time by design: BEACON does not inject tags at runtime, because runtime injection is invisible to the social and AI scrapers that do not run JavaScript. This is a deliberate divergence from the runtime-component shape of the other Polymathie primitives.
- Family hygiene: Apache-2.0 license and notice, zero-dependency core, framework binding as an optional peer, and the Polymathie family section in the README.
